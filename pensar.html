Antes de escribir código

Cómo pensar un ejercicio antes de construirlo

Escribir código es la última parte, no la primera. Este método en 6 pasos ayuda a planear cualquiera de los proyectos de Proyectos antes de tocar el teclado, para llegar con una idea clara de qué vas a construir y por qué.

El método en 6 pasos

1

Entiende el objetivo

Antes de programar nada, describe con tus propias palabras qué debe hacer la app y para quién. Si no puedes explicarlo en una frase, todavía no está claro.

Pregúntate: ¿qué va a ver el usuario en pantalla cuando la app esté terminada?

2

Identifica el estado

El estado es todo dato que cambia mientras se usa la app: un número, una lista, un texto, un booleano de "activo/pausado". Antes de escribir HTML o CSS, anota qué datos vas a necesitar guardar.

Pregúntate: ¿qué cambia con el tiempo o con las acciones del usuario, y qué se queda fijo?

3

Divide el problema en piezas pequeñas

No intentes construir la app entera de una vez. Separa: el HTML mínimo, un solo evento, una sola función. Cada pieza debe poder probarse por separado.

Pregúntate: si solo pudiera hacer una cosa hoy, ¿cuál sería la más pequeña que ya se pueda ver funcionando?

4

Escribe pseudocódigo antes de código real

En español, paso a paso, sin sintaxis: "cuando el usuario haga clic, leer el valor del input, comprobar que no esté vacío, añadirlo a la lista". El código real solo traduce esto.

Pregúntate: ¿podría explicarle estos pasos a alguien que no sabe programar?

5

Identifica los eventos que disparan cambios

Casi toda interacción parte de un evento: un clic, una tecla pulsada (input), un envío de formulario, o el paso del tiempo (setInterval). Decide cuál es el disparador antes de escribir la función que reacciona a él.

Pregúntate: ¿qué acción concreta del usuario (o del reloj) debe iniciar cada cambio?

6

Construye, prueba los casos límite y refactoriza

Implementa el camino feliz primero. Después pruébalo a propósito con datos vacíos, con 0, con números negativos o con texto raro. Solo cuando funciona, mejora el nombre de las variables y limpia el código repetido.

Pregúntate: ¿qué pasa si el usuario no hace lo que yo esperaba que hiciera?
